# wheel-owners

**Проверка конфликтов путей установки в локальном наборе Python wheel до установки.**

[English](../README.md) · [简体中文](README.zh-CN.md) · Русский · [Deutsch](README.de.md)

`wheel-owners` вычисляет целевые пути файлов для явно заданных wheel и схемы
установки. Он сообщает о нескольких владельцах одного файла и о конфликтах
между файлом и каталогом. Используется фиксированная версия
`installer==0.7.0` с адаптером, который только записывает результат моделирования.
Проверяемые пакеты не устанавливаются; их код не импортируется и не выполняется.

Успешная проверка означает лишь отсутствие конфликтов владения в поддерживаемой
модели для переданных файлов. Она не гарантирует совместимость зависимостей,
корректность импортов, совместимость ABI или безопасность пакетов.

## Быстрый старт

Нужен Python 3.10 или новее на POSIX-системе. В каталоге исходного кода:

```sh
python -m pip install .
wheel-owners --layout examples/posix-layout.json a.whl b.whl
```

Замените `a.whl` и `b.whl` настоящими именами локальных wheel. Эти инструкции
не предполагают, что проект опубликован на PyPI. Установка самого инструмента
может загружать зависимости; команда проверки не обращается к сети.

Перечислите все нужные артефакты, включая уже выбранные зависимости.
Инструмент не разрешает зависимости, не скачивает пакеты, не обходит каталоги
рекурсивно и не проверяет существующее окружение. Для каждого нормализованного
имени дистрибутива допускается только один артефакт: выбор между версиями или
платформенными сборками нужно сделать заранее.

## Схема установки

Параметр `--layout` принимает строгий JSON. Поддерживается только профиль
`posix-case-sensitive-v1`:

```json
{
  "profile": "posix-case-sensitive-v1",
  "interpreter": "/venv/bin/python",
  "scheme": {
    "purelib": "/venv/lib/python3.12/site-packages",
    "platlib": "/venv/lib/python3.12/site-packages",
    "scripts": "/venv/bin",
    "headers": "/venv/include",
    "data": "/venv"
  }
}
```

Все пять путей обязательны. Пути должны быть абсолютными нормализованными
POSIX-путями. Это параметры модели: инструмент не создаёт и не исследует эти
каталоги. Путь `interpreter` используется при генерации скриптов, но интерпретатор
не запускается. Адаптируйте пример к планируемой установке.

Сравнение путей строгое, по кодовым точкам Unicode. Нет нормализации Unicode,
моделирования нечувствительности к регистру в Windows или macOS, разрешения
символических ссылок или полной эмуляции реальной файловой системы.

## Какие случаи считаются конфликтами

- Несколько владельцев одного целевого файла, даже при одинаковом содержимом.
- Путь, который должен быть одновременно файлом и родительским каталогом.
- Пересечения путей исходных скриптов, сгенерированных console/GUI entry-point
  скриптов и других файлов, попавших в тот же каталог.
- Совпадения после отображения разных разделов схемы в один целевой путь.

Учитываются поддерживаемые отображения корня wheel и `.data`. Совместное
использование каталога само по себе разрешено: части namespace-пакета с разными
файлами могут пройти проверку. Это не доказывает корректность импортов.

## Результат

Команда выводит детерминированный JSON с `schema_version: 1`.

| Код завершения | Значение |
| --- | --- |
| `0` | В поддерживаемой модели конфликтов владения не найдено |
| `1` | Найдены конфликты владения |
| `2` | Некорректный ввод или неподдерживаемый случай; успешного вывода нет |

Детерминированность относится к одинаковым входным данным, схеме и версиям
инструмента и зависимостей. Некорректные wheel или пути, неподдерживаемые версии
или преобразования и повторные нормализованные имена дистрибутивов отклоняются.
Сбой процесса или отсутствие отчёта не означают успешную проверку.

Генерация байткода, выполнение `.pth`, import hooks и editable-установки
не моделируются. Полный перечень ограничений: [limits.md](limits.md).
